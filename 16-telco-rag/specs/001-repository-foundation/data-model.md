# Data Model: Repository Foundation (Stage 0)

**Feature**: [spec.md](spec.md) | **Date**: 2026-10-05

Stage 0 introduces no domain data. The "entities" here are the configuration
artifacts the foundation is built from (spec §Key Entities). They are recorded
as structured contracts so `/speckit.tasks` can enumerate exactly what each
artifact must contain and how it must behave.

Derived from: spec FR-001–FR-016, research D1–D10.

---

## Entity 1 — Project Manifest

The authoritative declaration of what the project requires to run. Single
source for environment preparation; must be machine-reproducible.
(FR-005, FR-006, FR-007, SC-004)

| Field | Type | Required | Constraint | Source |
| --- | --- | --- | --- | --- |
| package name | string | yes | `telco-rag` exactly | Constitution §10, FR(overview §5.1) |
| version | semver | yes | `0.1.0`, synchronised with pyproject only source | D6, single-sourcing |
| minimum runtime | string | yes | `>=3.12` | Constitution §32, FR-007 |
| runtime dependency set | list | yes | empty at Stage 0 (D3 deviation) | D3 |
| dev dependency group | list | yes | `{pytest, ruff, mypy}` only | FR-005, D3 |
| locked constraints | file | yes | committed `uv.lock`, generated by `uv lock` | FR-006, SC-004 |
| local runtime pin | string | yes | `.python-version` = `3.12` | D2, FR-008 |

**Validation rules**

- Manifest MUST parse as valid TOML.
- Package name MUST be `telco-rag`.
- `requires-python` MUST accept a 3.12 interpreter (`>=3.12`).
- Dev group MUST contain exactly the three declared tools and nothing else.
- Lockfile MUST be present, committed, and in sync with the manifest
  (`uv lock --check` passes).

**Derived value**

- `telco_rag.__version__` MUST equal the manifest version; it MUST be read from
  distribution metadata, never hard-coded independently (D6).

## Entity 2 — Verification Command

The one documented entry point for automated health checking. Composes the test
execution and quality gates; its result is the definition of "healthy".
(FR-001, FR-002, FR-003, FR-004, SC-001, SC-002, SC-003, SC-006)

| Field | Type | Required | Constraint |
| --- | --- | --- | --- |
| canonical invocation | string | yes | `make verify` (D1) |
| composed checks | ordered list | yes | `pytest` → `ruff check` → `mypy` |
| success result | exit code 0 | yes | all checks pass |
| failure result | non-zero exit | yes | first failing check halts the run |
| execution context | string | yes | every tool via `uv run` inside locked env |
| empty-run behaviour | bool | yes | MUST NOT report success when zero checks run (FR-003) |
| runtime bound | duration | yes | < 60 s checks phase (SC-002) |

**Validation rules**

- `make verify` MUST exit 0 on a clean tree and non-zero if exactly one composed
  check fails, with the failing check's output visible.
- When the suite is intentionally emptied, `make verify` MUST NOT report a
  passing result (FR-003 guard test — D6 test 3).
- When the local interpreter is older than the minimum runtime, `make verify`
  MUST surface an actionable message naming the mismatch (FR-007, SC-007).

## Entity 3 — Quality Gate

A named, version-controlled automated check with an explicit defect class it
detects, a pass/fail result, and a location when it fails.
(FR-009, FR-010, FR-011, SC-005, SC-006)

| Field | Type | Required | Constraint |
| --- | --- | --- | --- |
| gate id | string | yes | e.g. `ruff`, `mypy` |
| defect class | string | yes | static inspection / type analysis |
| configuration | file | yes | in `pyproject.toml` (`[tool.ruff]`, `[tool.mypy]`), version controlled |
| exit result | exit code | yes | 0 pass / non-zero fail |
| failure locator | string | yes | a detected defect MUST be reported with file:line (SC-006) |
| local-override flag | bool | no | MUST NOT require per-developer config (FR-010) |

**Validation rules**

- Both gates MUST run from the `make verify` entry point (D1).
- A seeded detectable defect MUST flip the gate to a failing result in 100% of
  trials, with a file:line locator (SC-005, SC-006).
- No contributor-local configuration file can alter gate results.

## Entity 4 — Repository Layout

The committed definition of the target structure and which directories exist at
which stage. Authoritative in exactly one place.
(FR-012, FR-013, FR-016, SC-009, SC-010)

| Field | Type | Required | Constraint |
| --- | --- | --- | --- |
| authoritative document | path | yes | `docs/architecture/overview.md` (FR-013) |
| stage-0 surface | set | yes | defined in plan.md §Project Structure |
| absent-directory rule | policy | yes | unreached-stage dirs absent, not empty (FR-012) |
| empty-dir mechanism | file | yes | `.gitkeep` for the three Stage-0 empty dirs (D5) |

**Validation rules**

- Exactly one document states the target layout; no stage document restates a
  divergent root tree (SC-009).
- The working tree contains none of: `prompts/`, `migrations/`, `frontend/`,
  `alembic.ini`, `agents/`, `src/telco_rag/{api,application,domain,ingestion,
  retrieval,query,generation,security,evaluation,observability,infrastructure,
  config}` (SC-010, FR-012).
- `docs/` continues to exist with all 22 documents reachable from README
  (FR-016).

## State transitions

Not applicable. These are static configuration artifacts (immutable at runtime,
per Constitution Principle X). The only lifecycle is *absent → present at its
stage*, which is a governance event, not a runtime state.

## Relationship map

```text
Project Manifest ──defines──▶ uv.lock (committed output)
        │
        ├── satisfies ◀── Verification Command (make verify)
        │                       │
        │                       ├── runs ──▶ Quality Gate: pytest  (tests)
        │                       ├── runs ──▶ Quality Gate: ruff    (static inspection)
        │                       └── runs ──▶ Quality Gate: mypy    (type analysis)
        │
        └── constrained by ◀── Repository Layout (docs/architecture/overview.md)
```
